# 생기부 세부특기사항 문장 생성기 (교사 대시보드) — 설계

> 작성일 2026-11-03. 대상: 교사(본인) 전용 대시보드 기능. 1차 통지표(임시 중간) 세특 문장 작성용.

## 왜 지금

학기에 통지표가 2번 나간다. **다음 주 중 1차 통지표**가 나가야 하고, 과목별로 **학생마다 약 2줄**의 세부특기사항(세특) 문장을 써야 한다. 대상은 정보 4개 반(마이크로비트 전까지, 22차 이하) + 주제선택 「디지털 마음 톡톡」 1기(화·목) + 진로탐색 「인간과 인공지능」 1기(화·목). (2기 선택과목은 이번 제외.) 손으로 전체 기록을 보고 쓰면 시간이 많이 든다. 2차 통지표는 12월 말에 나가며 **그때 문장과는 별개**다(이번 것은 임시 중간 평가 문장).

지금 교사 대시보드에는 CSV 내보내기(`/api/teacher/export`: 성찰·감정·출석·명렬표)만 있고, 세특 문장을 만들어 주는 기능은 없다. 새로 만든다.

## 무엇을 만드나 (목표)

교사 대시보드에 **세특 문장 생성·검토·내보내기** 기능을 추가한다. 세 덩어리:

1. **문장 생성** — 과목별로 학생 한 명씩, 그 과목에서의 활동·성찰 기록을 AI(Gemini)가 읽고 **교사 관찰 사실 위주의 2줄**로 압축해 초안을 만든다.
2. **표로 보기 + 교사 편집** — 생성된 문장을 과목 × 학생 표로 보고, 교사가 각 칸을 직접 다듬어 저장한다.
3. **엑셀로 내보내기** — 표를 파일로 내려받아 통지표 작업에 붙인다.

### 문장 규칙 (세특 서술 원칙)

김보연 선생님 유의사항을 그대로 따른다. AI 프롬프트의 핵심 제약:

- **현재형 종결어미 `~함`**으로만 끝낸다. 과거/미래시제·`~했음/~할 수 있음/~알 수 있었음` 금지 → `~함/~앎`.
- **교사 입장에서 관찰한 사실 위주**로 서술한다. (예: `활동지를 충실히 작성함`, `~에 대해 발표함`, `~하는 모습이 돋보임`, `~에 대해 심도 있게 탐구함`.)
- 종결어미는 유의사항의 예시 목록(활동함·표현함·설명함·발표함·제작함·작성함·탐구함·분석함·완성함·참여함 등)에서 자연스럽게 고른다.
- **전체 활동을 나열하지 않는다.** 1차 통지표는 2줄만 나가므로, 전체 기록에서 대표적인 활동 1~2개를 골라 압축한다.
- 분량: 대략 2문장 / **공백 포함 100~200자**를 기본 상한으로 둔다. *(내 결정 — 교사가 조정 가능.)*

### 과목별 입력 데이터 (프라이버시)

과목마다 **그 과목 세션에서의 그 학생 기록**만 본다.

- **정보(1~4반)**: 그 학생 반(정보 세션 = `groupKey` 없는 세션)의 성찰 답·활동 산출물(artifacts)을 사용. 성찰 내용은 활용해도 된다(민감하지 않음). ※ `teacherEvals`(교사평가)는 현재 진로탐색 7·8차 발표용으로만 존재하고 정보/마음톡톡엔 거의 없다 → 있으면 쓰고, 없으면 **학생 활동·성찰에서 뽑아 교사 관찰 형식(`~하는 모습이 돋보임`, `~을 충실히 작성함`)으로 서술**한다. 세특 자체가 교사가 확인·수정하는 초안이므로 관찰 형식 서술이 맞다. *(내 결정.)*
- **진로탐색(인간과 인공지능) 1기**: 분반 세션(`groupKey` ∈ `hai-tue-1`, `hai-thu-1`)의 성찰·활동 산출물 사용.
- **디지털 마음 톡톡 1기**: 분반 세션(`groupKey` ∈ `mt-tue-1`, `mt-thu-1`). **감정 글·마음일기·성찰 등 학생이 쓴 글 내용은 Gemini로 보내지 않는다** — 이 과목의 1순위 원칙. 대신 **학생이 안 쓴, 교사/차시가 만든 정보 + 참여 사실만** AI에 보낸다:
  - 차시 제목·활동 이름(교사가 지은 것) 목록
  - 각 활동의 **작성함/미작성 여부(불리언)** — 학생 글의 비어있음만 서버에서 판정, **텍스트 자체는 전송 안 함**
  - 출석·참여 횟수 집계
  AI는 이것만 보고 "~에 꾸준히 참여함 / ~활동을 성실히 작성함" 류의 **활동 사실** 문장을 만든다. 감정·내면 서술은 프롬프트로 금지. *(내 결정 — 필드 차원의 허용/차단 목록을 코드로 강제. 정보/진로탐색의 성찰 활용과 다른 점.)*
- **공통**: 지금까지 포털 원칙대로 **학번·이름은 Gemini로 보내지 않는다.** 활동/성찰 **텍스트만** 보낸다(`comfort-bot`·`ai-review`·`ai-feedback`와 동일).

### 통지표 회차(라운드)

이번은 **1차(임시 중간)**. 12월 말 2차는 별개 문장이다. 생성·편집 결과를 저장할 때 **회차(round) 값을 함께 저장**해, 2차 작업이 1차 문장을 덮어쓰지 않게 한다. 기본 회차는 `1`. *(내 결정.)*

### 1차 범위 (반영할 활동) — 교사 확정

- **정보(1~4반)**: **마이크로비트 아크 시작(23차) 전까지** = `lessonNo ≤ 22`. 지금 진행 중인 마이크로비트 단원(23차~, 수행평가 미완)은 **제외**. (첫 마이크로비트 차시의 정확한 `lessonNo`는 빌더가 seed 스크립트로 확인해 경계 확정 — 메모리상 23차.)
- **선택과목(마음톡톡·진로탐색)**: **1기만.** 1기는 이미 끝난 분반이므로 1기 전체 회기를 반영. **2기는 이번 1차 통지표에서 제외**(아직 진행 중).
  - 포함 groupKey: `mt-tue-1`, `mt-thu-1`, `hai-tue-1`, `hai-thu-1` 만. `*-2`(2기)는 제외.

## 화면 (교사 대시보드)

교사 대시보드에 새 패널/페이지를 하나 더한다(기존 패널 구조·`requireTeacher` PIN 가드를 그대로 따른다).

- **과목 선택 탭/필터**: 정보 전체(또는 1·2·3·4반), 마음톡톡 1기, 진로탐색 1기.
- **표**: 한 줄 = 과목 × 학생. 열 = `과목 | 반/분반 | 학번 | 이름 | 세특 문장(편집 칸) | 상태 | 글자수`.
  - 상태 = 미생성 / 생성됨(초안) / 수정됨(교사 저장).
  - 세특 문장 칸은 편집 가능한 textarea. 교사가 고치고 **저장**하면 Firestore에 남는다.
- **버튼**: `선택 생성` / `과목 전체 생성`(AI 초안 채우기), `저장`, `엑셀로 내보내기`.
- 학생 화면에는 절대 보이지 않는다(교사 전용).

## 저장 (데이터 모델)

새 컬렉션 `recordComments`(가칭). 문서 ID = `${round}__${subjectKey}__${studentId}` 형태로 과목·회차·학생당 1건.

- 필드(안): `round`, `subjectKey`(예: `info-1` ~ `info-4`, `mt-1기`, `hai-1기`), `studentId`, `classNo`/`groupKey`, `text`, `status`(draft/edited), `updatedAt`, `model`.
- 교사만 쓰고 읽는다. *(세부 필드명은 빌더가 기존 타입 규칙에 맞춰 확정.)*

## 내보내기

기존 `/api/teacher/export`의 **CSV(UTF-8 BOM)** 방식을 따른다 — 엑셀에서 바로 열린다(한글 안 깨짐). 열 = `과목 | 반/분반 | 학번 | 이름 | 세특 문장`. 선택한 과목(또는 전체)·현재 회차 기준으로 내려받는다. *(내 결정 — 진짜 `.xlsx` 바이너리가 꼭 필요하면 교사 확인 후 라이브러리 추가. 기본은 CSV.)*

## 만드는 방법 (스택)

- 기존 포털 그대로: Next.js(이 저장소 버전, `node_modules/next/dist/docs/` 확인), Firebase Admin, 교사 PIN 가드, Gemini raw fetch(`GEMINI_API_KEY`, `gemini-flash-latest`) — `ai-review.ts` 패턴 재사용.
- AI 호출은 `import "server-only"` 서버 모듈. 이름/학번 미전송 원칙을 코드로 강제.

## 하지 않는 것 (non-goals / anti-goals)

- **12월 2차 통지표 문장 작성** — 이번 범위 아님(회차만 분리해 둠).
- **활동 전체 나열** — 2줄 압축만.
- **마음 톡톡 감정/내면 서술** — 활동 사실 수준만. 감정 글 내용은 AI로 보내지도, 문장에 쓰지도 않는다.
- **학생에게 노출** — 교사 전용.
- **학번·이름을 AI로 전송** — 금지.
- 자동 확정/일괄 제출 — AI는 초안까지만, 최종 문장은 교사가 손본 것.

## 빌더에게 남기는 것

- Firestore 컬렉션/필드명·타입은 기존 `src/lib/types.ts`·`db.ts` 관례에 맞춰 확정.
- 과목 전체 생성 시 Gemini 호출 묶음 처리(동시성·타임아웃·AI 쿼터 `ai-quota.ts`) 방식.
- 성찰/활동 텍스트가 없는 학생(결석·미제출) 처리: 생성 건너뛰고 상태를 "자료 부족"으로 표시.
- 표 페이지를 기존 대시보드 안 탭으로 넣을지 별도 경로로 둘지(기존 패널 구성에 맞춰).
