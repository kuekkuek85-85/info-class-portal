## 2. 목표

- 31차에서 배운 리스트를 똥피하기에 **적용**하고, AI로 나만의 기능을 더해 똥피하기를 마무리한다.
- 다섯 작품을 **입력 → 처리 → 출력**(센서 → 프로세서 → 액추에이터)으로 정리한다. 33~34차에 구성요소를 고를 때 쓴다.
- 수행평가(피지컬 컴퓨팅 프로젝트, 33~34차)를 안내한다.

## 3. 단계 구성 (45분)

`phaseOrder: waiting → build → grill → problem → assessment → reflection` (마음 체크인은 강제 관문)

| 순서 | phase | 화면 | 시간 |
|---|---|---|---|
| 1 | waiting + 체크인 | 파이썬 타자 링크, 마음 체크인 | 3분 |
| 2 | build | **미션① 리스트로 정리** (31차 미션② 그대로, 보기 골라 채우기) | 10분 |
| 3 | grill | **미션② AI로 나만의 기능** (31차 미션③ 그대로, 보너스) | 9분 |
| 4 | problem | **마이크로비트 정리** - 다섯 작품 입력·처리·출력 표 1장 + 확인 1문항 | 8분 |
| 5 | assessment | **수행평가 안내** - 탭 4개(한눈에 · 채점 기준 · 33~34차 흐름 · AI 규칙) | 11분 |
| 6 | reflection | 성찰 1문항 → UNO | 4분 |

- 1·2번이 31차 재사용이라 빠르게 간다. 시간이 모자라면 2번(AI)을 줄인다(질문 2).
- focusExempt: waiting, build(MakeCode 새 탭), grill(MakeCode 새 탭). problem·assessment 는 포털 안이라 면제 아님.

## 10. 교사 결정 반영 (2026-11-18 2차) - seed 제작 완료

- AI 미션은 **모두**(보너스 아님). 하드웨어는 **본체 내장 부품만**(외부 부품 없음). AI 는 33~34차 모두 **포털 AI만**.
- 수행평가 안내는 끝, 답 키는 mb32 새로, 채점 기준은 평가 계획 문구 그대로(안내 탭 「채점 ① 이해」·「채점 ② 구현」 표).
- 성찰 = 수행평가로 잇기: "마이크로비트로 해결하고 싶은 실생활 속 불편은 무엇인가요? (한두 줄)" (2026-11-23 교사 피드백: 학교생활에서 실생활로 넓힘, 주제 겹침 방지. 예시는 집·운동·건강 등 학교 밖 상황).
- 2026-11-23 교사 피드백: 총정리의 입력·출력 고르기(mb32_want_in·out)를 성찰 바로 앞 "성찰 ①" 단계(mvp)로 옮김. 성찰 화면은 활동지 문항을 못 그려서(프론트 변경 필요) 단계를 따로 둔다. 키·활동 ID 는 그대로.
  - 성찰은 원래 reflections 에만 남아 다음 차시가 못 읽는다. 세션 `reflectionAnswerKey: "mb32_pa_problem"` 이면
    성찰 저장 API 가 같은 글을 학번별 공유 답안 문서(artifacts/microbit-makecode__학번)의 그 키에도 저장한다.
  - **33차는 `echoKeys: [{ key: "mb32_pa_problem", label: "32차에 적은 불편" }]` 로 다시 보여 주면 된다.**
    같은 방식으로 `mb32_want_in` · `mb32_want_out`(써 보고 싶은 입력·출력)도 33차 설계 단계에서 echo 가능.
- 총정리에 "써 보고 싶은 입력·출력 고르기"(multi 2개)를 넣었다(33차 구성요소 설계로 잇기).
- 제작물: scripts/seed-lesson32.ts, public/mb32-recap.svg · mb32-parts.svg · mb32-pa-flow.svg,
  scripts/open-info-32-31-1123.ts(11/23 열기, 준비만), 성찰 한 벌 저장(api/student/reflection, types).
