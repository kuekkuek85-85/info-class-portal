# 정보과 7차시 — 수행평가 완료 차시 설계

2026-08-29(토) 작성 · 수업일 2026-08-30

## 무엇을 만드는가

6차시에서 그린 그림과 밑기사(①②)를 이어받아, **③ 취재 · ④ 인터뷰를 붙여 신문기사
한 편을 완성하고 제출**하는 40분 차시. 수행평가 마감 차시다.

빨리 끝낸 학생이 남는 시간에 손을 놓지 않도록, 제출을 **3단계 루프**로 만든다.

```
쓰기 → 1차 제출 → AI 점검(즉시) → 고치기
     → 2차 제출 → 교사 피드백 → 고치기
     → 최종 제출
```

## 완료의 기준

**1차 제출이 곧 수행평가 제출물이다.** 2차·최종은 여유 있는 학생을 더 올리는 장치이지
완료 조건이 아니다.

이유: 28명 × 40분에서 교사 피드백을 전원에게 주려면 교사 한 사람에게 14분이 직렬로
쌓인다. 먼저 낸 학생은 기다리고 늦게 낸 학생은 차례가 오지 않는다. 종이 칠 때
"미완성" 인 학생이 생기는 설계는 수행평가에 쓸 수 없다.

예상 도달: 1차 25~28명 · 2차 15~20명 · 최종 6~10명.

## 40분 배분

| 단계 | 분 | 하는 일 |
|---|---|---|
| 기분 체크 | 3 | |
| 그림 마무리 | 4 | 6차시 그림 이어서. 끝낸 학생은 바로 아래로 |
| 기사 완성 + 루프 | 30 | ③④ 쓰기 → 1차 → AI → 2차 → 교사 → 최종 |
| 성찰 | 3 | 한 줄 |

**기분 체크는 마감 차시에도 넣는다.** 매일 하는 루틴이라 이 날만 빼면 그 자체가
신호가 된다 — 오늘은 평가라서 다르다는. 3분은 그림(5→4)과 루프(32→30)에서 낸다.

**그림은 4분이면 된다.** 6차시에 이미 20분을 그렸다. 남은 것은 안 끝낸 학생의 마무리와
이름표 보강이다.

**③ 취재는 한 건만, 한 줄로.** 검색이 길어지면 1차 제출이 25분에 몰려 루프가 한 바퀴도
안 돈다. 막힌 학생을 위해 「사례 보기」 칩을 단다.

교실에서 이렇게 흐른다.

```
0–3분    기분 체크
3–7분    그림 마무리
7–19분   ③④ 쓰기 · 검색 (빠른 학생은 14분쯤 1차 제출)
19–26분  1차 제출이 몰림 → AI 점검 즉시 → 고치기
26–37분  2차 제출 → 교사가 돌며 피드백 → 최종 제출
37–40분  성찰 · 마침
```

교사가 대기 줄을 도는 창은 **11분**이다. 한 명에 5초씩이면 넉넉하지만, 한 명을 붙잡고
길어지면 뒤가 밀린다. 밀리면 밀리는 대로 둔다 — 1차 제출이 이미 제출물이다.

## 왜 활동지 안에 넣는가

제출·AI·교사 피드백을 **활동지 맨 아래 한 칸**에서 처리한다. 단계가 오를 때 그 칸의
내용만 바뀐다.

단계(`LESSON_PHASES`)를 새로 파는 안은 버렸다. 교사가 전체를 한꺼번에 넘겨야 해서
빠른 학생이 느린 학생을 기다리게 되는데, 그건 이 설계의 취지와 정반대다. **학생마다
진도가 다른 것이 전제**다.

## 활동 통

`career-plan` — 5·6차시와 같다. 그림과 ①② 가 같은 artifact 에 있으므로 그대로 이어진다.
6차시 답은 echo(읽기 전용)가 아니라 **편집 가능한 칸**으로 띄운다. 마감 차시라 다듬을
수 있어야 한다.

## 활동지 문항

| 키 | 칸 | 출처 |
|---|---|---|
| `news_title` | 제목 | 6차시 |
| `news_scene` | ① 현장 | 6차시 |
| `news_change` | ② 무엇이 바뀌었나 · 왜 | 6차시 |
| `news_real` | ③ 이미 시작되고 있다 — 취재 | **신규** |
| `news_interview` | ④ {이름} 씨 인터뷰 | **신규** |
| (기존 `sources`) | 출처 | 활동 기본 칸 재사용 |
| `news_check2` | 2차 전 자기 점검 | **신규** (`choice`) |
| `news_caption` | 사진 설명 — 기다리는 동안 | **신규** |
| `news_template` | 어떤 지면으로 낼까요 | **신규** (`choice`) |
| `submit` | 제출 칸 | **신규 문항 종류** |

## AI 점검 — 정량적인 것만

**정성 평가를 하지 않는다.** 내용이 좋은지, ②의 '왜'가 충분한지는 교사의 몫이다.
AI 자리는 기계가 셀 수 있는 것만 본다.

그래서 **대부분 코드로 판정한다.** 빈 칸과 글자 수는 세면 안다. 즉시 뜨고, 틀리지 않고,
호출이 몰리지 않고, 실패하지 않는다. Gemini 가 필요한 것은 오탈자 하나뿐이고 그마저
실패하면 그 줄만 빠진다.

### 판정 항목

1. **빈 칸** — 제목 · ① · ② · ③ · ④
2. **짧은 칸** — 제목 5자 · ① 60자 · ② 80자 · ③ 40자 · ④ 40자 (조정 가능)
3. **출처 비었음** — 결함이 아니라 **질문**으로 띄운다
4. **오탈자 후보** — AI. 최대 3개

### 문장 규칙

- 무엇을 할지가 문장에 들어 있어야 한다. "왜 그렇게 생각했나요?" 같은 되묻기는 쓰지
  않는다 — 아이가 교사에게 "무슨 말이에요?" 를 들고 온다
- 항목마다 **고칠 칸으로 가는 단추**를 단다
- 출처는 "안 찾고 쓴 게 맞나요? **맞다면 그대로 두셔도 됩니다**" 로. 일부러 비우는
  학생이 있다. 한 번 묻고 두 번은 묻지 않는다
- 오탈자는 "이 낱말 한 번만 볼까요" 로. 고치라고 단정하지 않는다 — 방언이나 일부러
  쓴 말을 잘못 짚을 수 있고, 틀렸다고 하면 위축된다

## 제출 칸 — 단계마다 다른 얼굴

```
0차  [ 1차 제출하기 ]

1차  확인해 주세요
       ④ 인터뷰가 비어 있어요                 → [④ 칸으로]
       ③ 취재가 조금 짧아요                    → [③ 칸으로]
       출처를 안 적으셨네요. 안 찾고 쓴 게 맞나요?
       맞다면 그대로 두셔도 됩니다             → [출처 칸으로]
       이 낱말 한 번만 볼까요 — "만드러"

     2차로 내기 전에, 소리 내어 한 번 읽어 보세요
       ○ ②의 '왜'가 한 문장으로 보인다
       ○ 읽어 보니 ②의 '왜'가 약한 것 같다
       ○ ③이 ①② 와 따로 노는 것 같다
       ○ 잘 모르겠다 — 선생님께 여쭙겠습니다

     [ 고쳤어요 · 2차 제출 ]  [ 그냥 넘어가기 ]

2차  선생님이 보고 계세요 (기다리는 동안 더 고쳐도 됩니다)

     그동안 — 그림 아래에 붙일 사진 설명을 한 줄 써 볼까요?
     ┌────────────────────────┐
     └────────────────────────┘
       ↓ 도착하면
     선생님: (칩) + (한 줄)
     [ 고쳤어요 · 최종 제출 ]

3차  제출 완료 ✓  → 완성된 신문 지면
```

「그냥 넘어가기」는 남긴다. 오탈자 호출이 실패해도 학생을 세우지 않는다.

## 대충 고치고 넘어가는 길을 막는다

중1은 피드백을 오래 고민하지 않고 금방 고쳐 버린다. 그러면 **20분대에 전원이 교사
대기열로 몰린다.** 교사가 도는 창은 11분이고 한 명에 이동까지 30초씩이면 22명은
차례가 오지 않는다 — 시간이 남는 것보다 나쁘다. "선생님 오세요" 하고 앉아 있게 된다.

세 가지로 막는다.

### 1. 2차 제출 문턱

「고쳤어요」를 눌러도 **실제로 안 고쳤으면 넘어가지 않는다.** 코드로 세는 값이라
확실하다.

```
아직 남았어요
  ③ 취재가 22자예요 (40자는 넘겨 주세요)   → [③ 칸으로]
```

**문턱은 빈 칸과 최소 길이만이다.** 출처는 일부러 비울 수 있으니 제외하고, 오탈자도
오탐이 있으니 제외한다. 문턱이 학생을 가두면 안 된다.

### 2. 자기 점검 한 칸

판단은 **학생이 한다.** AI 가 정성 평가를 하지 않는다는 원칙은 그대로다.

그리고 여기서 아래 세 개를 고른 학생이 곧 교사가 먼저 가 봐야 할 학생이다 —
**대기 줄을 그 순서로 세운다.** 스스로 "약한 것 같다" 고 한 학생이 앞에 온다.

### 3. 기다리는 동안 할 일 — 사진 설명

차례를 기다리는 화면에 **사진 설명(캡션) 한 줄**이 열린다. 실제 신문의 요소이고,
그림과 기사를 잇는 일이라 평가 방향에도 맞는다. 한 줄이라 부담이 없다.

`news_caption` 키로 저장한다.

## 완성본 — 신문 지면

최종 제출한 학생에게 **완성된 신문 면**을 보여준다. 교사도 같은 지면을 본다.

`CardNews` 가 이미 그림 + 활동지 답을 한 장으로 묶고 있고 갤러리·내 작품·교사 열람이
전부 그것을 쓴다. 신문 지면은 **그 자리에 얹는 다른 판형**이다 — 새 구조를 만들지 않는다.

지면은 활동지 마지막 `choice` 문항으로 고른다 (`news_template`). 새 문항 종류가 필요 없다.

| 값 | 지면 |
|---|---|
| `top` | 1면 톱 — 제호 아래 제목 크게, 사진 크게, 본문 2단 |
| `interview` | 인터뷰 중심 — ④ 를 큰 따옴표로 앞세운다 |
| `photo` | 사진 특집 — 그림을 지면 가득, 글은 아래로 |

제호는 「2036 미래신문」 고정. 기자 이름은 `{이름} 기자` 로 자동 치환한다 (6차시의
`named()` 그대로).

## 구현 순서와 자를 선

| # | 무엇 | 없으면 |
|---|---|---|
| 1 | 7차시 수업 등록 (seed) | 수업이 안 열린다 |
| 2 | 제출 칸 (3단계 루프) | 루프가 없다 |
| 3 | 코드 점검 + 2차 문턱 | 대충 넘어간다 |
| 4 | 오탈자 AI | 그 줄만 빠진다 |
| 5 | 제출 API · 교사 검토 API | 저장이 안 된다 |
| 6 | 대기 줄 + 소리 | 교사가 못 본다 |
| 7 | 교사 검토 화면 (✓✗ · 칩 · 한 줄) | 피드백을 못 준다 |
| 8 | 자기 점검 · 사진 설명 | 대기열이 몰린다 |
| **9** | **신문 지면 3종** | **기존 카드로 보인다 — 수업은 된다** |

**1~8 이 수업을 돌리는 최소한이고 9 는 없어도 된다.** 시간이 모자라면 9 만 다음으로
미룬다.

## 교사 화면

### 대기 줄

대시보드 위에 **「검토 대기 N명」**. 기존 20초 폴링에 실린다. 새 이름이 뜰 때 **짧은
소리**를 낸다 — 교실을 돌아다니는 중에 화면을 계속 보지 않아도 되게.

**푸시 알림은 없다.** 이 앱에 푸시가 없고 이번에 만들지 않는다. 폰 화면이 잠기면 폴링이
멈춘다. 실제 운영은 "폰을 손에 들고 대기 줄을 본다" 이지 "알림이 온다" 가 아니다.

### 한 학생을 열면

```
3번 김○○                          2차 제출 18:31

AI가 1차에서 짚은 것 (18:24)
  ✓ ④ 인터뷰가 비어 있었음          고쳤습니다 (87자)
  ✗ ③ 취재가 짧았음                 아직 22자
  ? 출처 없음 — 물어봤음            그대로 두었습니다
  ✓ 오탈자 "만드러"                 고쳤습니다

[제목] [①] [②] [③] [④]  ← 기사 본문

선생님 피드백
 ┌──────────────────────────────┐
 │                              │   ← 본체
 └──────────────────────────────┘
 [②의 '왜'가 더] [①이 그림에 없어요] [③이 잘 이어지네요]
 [④가 따로 노는 것 같아요] [좋아요 · 최종 제출하세요]
                                        [ 보내기 ]
```

**✓✗ 는 다시 세어서 나온 값이다.** 학생이 "고쳤어요" 를 눌러도 실제로 안 고쳤으면 ✗ 다.
**교사가 여는 순간 다시 센다** — 기다리는 동안 더 고쳤으면 그것이 반영되어, 교사가 보는
글과 표시가 어긋나지 않는다.

**출처는 ✗ 가 아니라 `?`** 다. 안 찾고 쓴 것이 맞을 수 있으므로 결함으로 표시하지 않고
"물어봤고 그대로 두었다" 로만 남긴다.

**입력칸이 칩보다 크다.** 정성적 피드백이 본체이고 칩은 보조다.

**작은 화면을 전제로 만든다.** 기사 본문은 접어 두고 대기 줄과 칩·입력칸을 먼저 보인다 —
교사는 학생 자리로 가서 **학생 태블릿으로 글을 읽고**, 폰으로는 피드백만 남긴다.

## 저장 구조

artifact 문서에 붙인다.

```ts
submitStage: 0 | 1 | 2 | 3
aiCheck?: { at: number; items: { code; field; kind; label; detail? }[] }
teacherFeedback?: { at: number; chips: string[]; note: string }
```

`aiCheck.items` 는 1차 시점에 저장하고, 반영 여부는 **읽을 때 다시 계산한다.** 스냅샷을
따로 쌓지 않는다.

## 읽기 비용

`submitStage` 를 **출석 문서에 실어** 대시보드가 추가 읽기 없이 대기 줄을 안다
(PRD 10장 D2 — 새 학생별 데이터는 attendance 에 태운다).

기사 본문은 교사가 그 학생을 누를 때만 artifact 1건을 읽는다.

## 다른 차시에 미치는 영향

없다. `submit` 문항 종류가 없는 차시에서는 그려지지 않는다. 기존 `ai_review` 종류는
건드리지 않는다 — 「디지털 마음 톡톡」이 쓰고 있다.

## 남은 위험

- **1차 제출이 18~25분에 몰린다.** 코드 판정이라 서버 부담은 없지만, 오탈자 호출은
  그 구간에 몰린다. 실패해도 그 줄만 빠지므로 수업은 멈추지 않는다
- **AI 피드백을 보고 교사에게 오는 질문은 막을 수 없다.** "무슨 말이에요?" 는 문장을
  지시문으로 써서 줄이고, "내 사례가 맞나요?" 는 교사가 답할 질문으로 남긴다
- **교사가 폰으로 칩을 누르는 동작이 수업 진행과 겹친다.** 한 명에 5초를 넘기면
  대기 줄이 밀린다
