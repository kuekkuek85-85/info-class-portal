# 정보 25차시 설계 — 「만보기 + AI로 기능 추가」

- 날짜: 2026-10-25. 마이크로비트 아크(24차 나만의 LED 애니메이션) 다음 차시.
- 교사 브레인스토밍 확정. 제작은 informatics 담당에게 위임.

## 의도 (왜)
움직임(흔들기=가속도 센서)과 **변수**를 익히고, **AI로 기능을 더하는** 체험을 한다. 수행평가의 '코딩에 생성형 AI 활용 가능' 으로 자연스럽게 잇는다. 아크 전체: [[microbit-arc-plan]] (만보기 → 가위바위보/주사위 → 똥피하기 → 수행평가 → createAI).

## 25차 구성 — 3미션
- **미션1 (만보기 ①)**: `걸음` 변수를 0으로 만들고, 화면에 걸음 수를 출력한다.
- **미션2 (만보기 ②)**: **흔들면** 걸음을 1 늘리고, 화면에 걸음 수를 출력한다. (흔들기 = 가속도 센서 이벤트 + 변수 증가)
- **미션3 (AI로 기능 추가 — 마이크로비트 바이브 코딩)**: 학생이 **말로 기능을 요청**(예: "A+B 버튼 누르면 0으로 초기화") → AI가 **만보기 전체에 그 기능이 더해진 완성 MakeCode-Python 코드**를 생성 → 학생이 **복사해 MakeCode에서 실행**. (추가분만이 아니라 **전체 코드**를 준다 — 교사 확정.)

## 방식 (24차 관례 계승)
- **미션1·2**: 뼈대 코드를 `code` 필드(복사 가능)로 주고, 각 `# (미션)` 빈칸을 학생이 채운다. "기존 코드 모두 지우고(Ctrl+A→Delete) 맨 처음에 붙여넣기" 명시. **코드 복사하기 바로 밑에 MakeCode 열기** 버튼(24차와 동일).
- **미션3**: 바이브 코딩 패널 — 학생 프롬프트(말로 기능) → AI 생성 코드(만보기 전체+기능) → **코드 복사하기 → 바로 밑 MakeCode 열기** → 붙여 실행.
- **적은 줄**(느린 속도). 대기=파이썬 타자 도우미, 성찰 보상=스네이크, 되돌아가기 off, activityId `microbit-makecode`(이어쓰기).
- 이어붙이기+빈칸 채우기 방식: [[makecode-paste-fill-missions]]

## 목표/비목표
- 목표: 변수(만들기·증가·출력) + 흔들기(가속도) 이벤트 + **AI로 기능 추가** 체험.
- 비목표: 긴 코드·고난도. 미션3에서 AI가 틀린 코드를 줄 수 있음은 '같이 고쳐 보는' 재료로 둔다(채점 아님).

## 제작 메모 (informatics, build-time)
- **★ 미션3 핵심 — 바이브 코딩을 마이크로비트용으로**: 기존 바이브 코딩(22차, 파이썬 터틀 똥피하기용: `src/components/vibe-code-panel.tsx`, `src/app/api/student/vibe-code`, `src/lib/vibe-code.ts`)을 **마이크로비트 MakeCode-Python용으로** 바꾸거나 변형. AI(Gemini)가 **만보기 기본 코드를 바탕으로** 요청 기능을 더한 **전체 MakeCode-Python 코드**를 생성하도록 시스템 프롬프트·기본 만보기 코드를 구성. 생성 코드 UI는 24차 애니메이터처럼 '코드 복사하기 + 바로 밑 MakeCode 열기'. **코드 변경·배포 대상.**
  - 흔한 요청(A+B 초기화, 소리/아이콘 추가, 버튼으로 증감, 속도 등)으로 **실제 makecode.microbit.org에서 생성 코드가 붙여넣기·블록 변환·동작** 하는지 검증. MicroPython/터틀 아님에 주의(MakeCode static Python).
- **걸음 변수 이름**: 한글 `걸음` 이 MakeCode-Python에서 유효한지 에디터로 확인(안 되면 `steps` + 한글 라벨).
- 미션1·2 뼈대 코드와 vibe-code 기본 만보기 코드를 실제 에디터에서 검증(붙여넣기·블록 변환).
- 차시 구조·관례는 24차(`scripts/seed-lesson24.ts`) 계승: 대기=타자, 보상=스네이크(세션 반영부 포함), freeNav off, 미션 단계(build/grill 등 슬롯+phaseLabels), 코드복사+MakeCode열기, hideDoneButton·공유 링크 제출은 24차에 맞춰 판단.
- 커밋·배포·세션오픈은 메인이. 작성 후 메인이 검토→등록→(교사 확정 시)오픈. 리허설로 학생 화면 검증 권장.
