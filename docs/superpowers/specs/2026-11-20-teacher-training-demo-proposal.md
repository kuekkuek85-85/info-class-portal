### 1. 교시 시각표 밖 시간에 코드가 만료되는가 - **해결 (조건부)**
- 코드는 `status == "active"` 이고 `isSessionClosed` 가 거짓일 때만 열린다: `src/lib/db.ts:447-460`, `src/app/api/student/code/route.ts:28-44`.
- 시각표를 아는 교시면 교시 끝+10분에 닫힌다: `src/lib/db.ts:359-360`, `src/lib/timetable.ts:83,108-112`. 11/23 은 정상 시간표(1~7교시, 7교시 15:55 끝): `src/lib/timetable.ts:60-74`.
  - 그래서 **1~7교시로 열면 20:00 에는 이미 닫혀 있다.**
- 시각표에 없는 교시(8교시)는 교시 만료가 없고, **시작 후 6시간** 상한만 걸린다: `src/lib/db.ts:321,362-363`. 진짜 수업도 8교시를 쓸 수 있다: `src/app/api/teacher/sessions/route.ts:115`.
- 시작 시각은 「수업 시작」을 누를 때 찍힌다: `src/lib/db.ts:575-577`. **오후 2시 전에 시작하면 20:00 전에 닫힌다** → 19:30 이후 시작.
- 학번 확인·확정 단계도 같은 판정을 다시 한다: `src/app/api/student/identify/route.ts:34-35`, `src/app/api/student/confirm/route.ts:41-42`. 코드 토큰 10분, 학생 쿠키는 그날 자정까지: `src/lib/session.ts:25,87`.
- 리허설 세션은 날짜가 바뀔 때만 닫힌다: `src/lib/db.ts:351`(리허설용).
- 조치안: 연수 세션 = `2026-11-23`, **8교시**, `rehearsal: false`, 19:30 이후 시작. 코드 변경 불필요.

### 2. 종료 안 한 세션이 다음 교시에도 선택되는가 (D4) - **미해결 (운영으로 우회)**
- 대시보드·공유 화면의 기본 선택은 `active` → 지금 교시 → 안 끝난 것 → 첫 수업 순이고, **이미 시각으로 닫힌 세션을 거르지 않는다**: `src/lib/pick-session.ts:22-30`, `src/app/api/teacher/dashboard/route.ts:136`.
- 지난 수업을 `ended` 로 바꾸는 정리(`closeExpiredSessions`, `src/lib/db.ts:384-401`)는 세션 목록 API 에서만 5분 간격으로 돈다: `src/app/api/teacher/sessions/route.ts:58-66,77,145`. 대시보드 API 는 부르지 않는다.
- 위험: 낮 6교시 1-3(코드 13)을 「수업 종료」 없이 두면 status 가 `active` 로 남아, 저녁에 대시보드를 열자마자 **1-3 실제 학생의 이름·감정 이유·성찰이 기본으로 뜰 수 있다**. 연수 세션이 active 가 돼도 목록이 교시순(`src/lib/db.ts:412`)이라 6교시가 8교시보다 먼저 잡힌다.
- 학생 쪽 혼선은 없다: 1-3 코드는 15:10 에 닫혀(`isSessionClosed`) 저녁에 코드 13 을 쳐도 못 들어간다. 연수 코드는 남은 번호에서 따로 뽑힌다(`src/lib/db.ts:473-509`).
- 조치안 (운영, 코드 변경 없음)
  1. 낮 수업 4개는 각 교시 끝에 「수업 종료」(평소대로).
  2. 19:30 점검 때 대시보드 날짜 11/23 의 4개가 모두 「종료」인지 확인. 남은 것이 있으면 그 자리에서 「수업 종료」.
  3. **화면 공유 전에** 대시보드 위 수업 버튼 줄에서 「8교시 · 교사 연수」를 직접 누른다. 줌 공유는 '창 하나'만(학생 화면 브라우저 → 대시보드 창 순서).
- 선택 코드안 A: `pickCurrentSession` 이 교시가 이미 끝난 세션을 후보에서 빼게 한다(`isPeriodOver` 로 거르기, 수 줄). 승인 시 브랜치 + 프리뷰 → 11/22(일) 반영.

1. **실제 학생 정보 노출 (가장 큼)**: 대시보드 기본 선택(D4), 수업 버튼 잘못 클릭, 채점 화면·명렬표·데이터·AI 조교 창. → 창 하나만 공유, 연수 세션 미리 선택, 다른 교사 화면은 열지 않기.
2. **이른 시작**: 19:30 전, 특히 14:00 전에 「수업 시작」을 누르면 6시간 상한으로 연수 중에 닫힌다. 8교시는 대시보드에 "저절로 닫힘" 표시가 안 뜨고(`src/app/teacher/dashboard/page.tsx:911-916` 는 교시 시각만 본다) 「수업 시작」 버튼도 active 동안 잠겨 있다(`:1051`). 닫혔으면 「수업 종료」 → 「수업 시작」 순서로 눌러 시작 시각을 새로 찍고(`src/lib/db.ts:577`), 단계를 다시 넘긴다(종료가 단계를 done 으로 바꾼다, `:580`).
3. **교시 오입력**: 1~7교시로 만들면 처음부터 닫혀 있다. 스크립트가 8교시를 고정하고, 실행 결과로 `period: 8` 을 확인한다.
4. **AI 지연·실패**: 15명이 동시에 보내면 응답이 늦을 수 있다. 미리 받아 둔 응답 화면(리허설 캡처)을 준비한다.
5. **표기 겹침**: 6반·7반 같은 번호가 「임시 90번」으로 같게 보인다. 10명 이하면 6반 자리만 배정해 피한다.
6. **외부인 입력 내용**: 참가자가 개인 정보나 부적절한 글을 적을 수 있다. 안내문에 "개인 정보는 적지 마세요" 를 넣었고, 연수 후 정리로 지운다.
7. **11/23 낮 수업과의 충돌**: 연수 세션은 다른 코드(50번대부터)·다른 문서 ID·다른 활동 통이라 학생 화면은 안 섞인다. 낮 수업 중에는 어떤 배포도 하지 않는다.
8. **원본 계획에 기대는 시드**: 시드는 실행 순간의 28~32차 계획에서 문항을 복사한다. 그 사이 원본 key 가 바뀌면 시드가 멈춘다(이름 바꾼 문항 없음을 오류로 알림). 반대로 원본을 고친 뒤 다시 돌리면 연수 판도 따라 바뀐다.
9. **로컬 화면 미확인**: 프로덕션 쓰기 금지라 연수 판을 실제 화면으로 아직 못 띄웠다. and_quiz 를 mvp 단계에, code_fill 을 problem 단계에 둔 것이 정상 표시되는지는 11/22 리허설에서 처음 확인한다.
